# Sane-Phonics

The extracted platformer demo and reusable gameplay systems for [Phonics](../../README.md). Install `@seanmorris/sane-phonics` alongside `@seanmorris/phonics`, or `seanmorris/sane-phonics` through Composer. The PHP namespace is `SanePhonics\`; this package supplies the old gameplay `PhpWasmEngine\` aliases until Phonics 1.0.

`phonics.json#game` plays the complete demo. `worlds/demo.world` includes the startup cards, title and menus. Other package-owned worlds select every existing course. The world properties `sane.scene`, `sane.profile`, and `sane.intro` configure this game. Browser scene/profile controls and legacy `bootEngine` calls remain supported by the demo host. Menus, level changes, vehicles, platformer tuning, rumble, text/dialog, phpinfo, camera behavior, outlines and streaming retain their existing behavior.

`phonics.json#platformer` independently registers movement and the `SanePhonics.Player` factory; `#player` exports that factory for Tiled. The module builds terrain from the session start map. Gameplay components and systems also remain individually available through PHP autoloading, without requiring demo startup. The game shares the session registry and scheduler with imported modules, spawns their Tiled factories, and retires those entities when their maps leave the level. Browser controls are optional; a host can provide only a canvas. The complete API and tuning documentation are maintained with the game in [phonics-examples](https://github.com/seanmorris/phonics-examples/tree/main/games/sane-phonics/docs).

The framework owns shared fonts, controller glyphs and generic shaders. This package owns course maps, gameplay art and water shaders. Development assets are generated by `examples/generate-assets.php`. The root commands aggregate this package's PHP and browser suites. Production manifests and archives exclude the generators, tests and scratch files.

Open `worlds/demo.tiled-project` in Tiled 1.12 or later after installing the repository dependencies with `npm install`. Enable the project extension when prompted, then open a course world. The project includes the portable custom classes, map/assets folders, and a relative extension path. Worlds name their modules in native Tiled lists; maps select `@sane/demo-map`, and the streaming world selects `@sane/spatial-maps`. Player start points use a nested `SpawnPoint` component, also available as `templates/spawn.tx`. Existing terrain and feature loaders remain game-owned; importing a spritesheet does not activate gameplay systems. Legacy `Player` points and the standalone player factory remain supported.
