# Tiled-Phonics

In an examples checkout, run `npm install` at the repository root and open the game's `.tiled-project` before its maps. Projects such as Sane's ship their custom classes and a relative extension directory; enable it when prompted. Sane also provides 34 concrete placement templates with nested settings. Its [course authoring guide](https://github.com/seanmorris/phonics-examples/blob/main/games/sane-phonics/docs/authoring.md) explains placement, local object links, and schema regeneration.

Tiled **1.12.2** integration for Phonics package URLs and world configuration. Install the packed/published `@seanmorris/phonics` and `@seanmorris/tiled-phonics` packages together, exposing the `tiled-phonics` command on Tiled's PATH (for example with a global npm install). Copy both `extension/*.mjs` files into Tiled's extensions directory, available through **Edit → Preferences → Plugins → Open**. Restart Tiled. Open a saved project and a world.

- **File → Add Package URL** imports a versioned `phonics.json`, verifies preview integrity, caches dependency metadata, templates and tilesets in `.phonics-cache`, registers classes and defaults, and saves `phonics.import.<alias>` on the world.
- **Phonics World Settings** selects the starting map and additional content modules from the imported pallets. Select modules used by any later streamed map as well as the starting map.
- **Attach Phonics Components** adds a class-valued property to selected objects or tiles, the current layer (including groups and image layers), the map, or the world. Bound classes construct components; unbound preset classes contain nested components. Fields stay inside their component: two classes can both define `speed` with independent defaults and overrides.
- **Phonics Scope Systems** selects already imported system sets and a retain, snapshot, reset, or custom lifecycle on the world or map. Selection also includes the required code in the world's initial module list. Runtime world changes load assets using already loaded code.
- **Phonics Tile Entities** selects disabled (default), collection, placement, or region mode on a map or selected tiles. Map defaults can be overridden per tile. Region connectivity uses shared edges unless diagonal corners are checked. Rendering and collision remain game decisions.
- **Place Phonics Entity** inserts an exported factory on the current object layer. Move the object and edit properties using the normal editor tools. Open cached tilesets or templates to use package previews.
- **Validate and Preview** saves assets, validates imports, references and typed properties, and opens the generic host with `?application=...&world=...`. Supply the executable PHAR URL and content world URL served by your static server; the extension does not generate game bootstrap code or publish local files.

Downloaded gameplay PHP and JavaScript are never executed by the editor importer. URL and `@alias/export` values remain strings. Actual local resources use file properties. Preview cache files preserve original URLs in supported `phonics.source`, `phonics.source.image`, `phonics.source.source` and `phonics.source.template` custom properties; template provenance is stored on its object so Tiled retains it. Worlds use only supported custom properties, not additional JSON keys.

The helper CLI exposes `tiled-phonics import MANIFEST_URL CACHE_DIRECTORY`, `tiled-phonics validate WORLD_FILE CACHE_DIRECTORY`, and `tiled-phonics open PREVIEW_URL`. Node 22 or newer is required. Package requirements use the runtime's exact, caret and minimum version grammar. See the [root guide](https://github.com/seanmorris/php-wasm-engine/blob/HEAD/README.md) for the package contract and the [release guide](https://seanmorris.github.io/php-wasm-engine/release.html) for the post-publication CDN check.

Component composition exports project class defaults to `phonics.classes.json` and records it as the world's `phonics.classes` file property. Save the `.tiled-project` before previewing: Tiled omits unchanged defaults from map files. Keep the generated catalog in the game's declared assets and refresh package integrity after changes. The CLI `tiled-phonics catalog PROJECT CACHE OUTPUT` can regenerate it for packaging. The validator rejects invalid classes, cycles, component references, and missing default file resources.

Local projects such as Noid's campaign ship explicit component bindings in that catalog. Saving defaults in the editor or regenerating the catalog retains those bindings even without a package cache. Cached package exports take precedence when available; bindings for deleted classes are removed.

`phonics.systems` and `phonics.modules` use native Tiled 1.12 list properties for export references. Edit entries directly in the Properties panel. Existing JSON-string lists remain readable; the systems dialog preserves legacy structured binding records (`id`, `use`, `options`, `after`) in their original encoding so their options are retained. `phonics.lifecycle` selects scope state handling. Existing factory-authored worlds remain supported without a component catalog.
